The Modern Way to Play Prey

An open-source engine and game-code replacement that runs the original 2006 game on today's Windows and Linux PCs, with modern display handling, a choice of OpenGL or Vulkan rendering and one game module for single-player and multiplayer.

Overview

openPREY replaces Prey's engine and game binaries with its own: a GPL engine built on openQ4 and a source-available game module built from the Prey SDK. The original campaign and multiplayer maps load from your retail game files.

openPREY does not include any Prey game data. You need your own copy of Prey (2006), from the original discs or another legitimate source.

openPREY is in early development. Representative campaign maps, save and load, and a two-client multiplayer session have been played on it, but full campaign completion and multiplayer parity are not claimed yet. See the technical reference for the compatibility status.

Highlights

Stock Content First

  • Finds CD-era installs through the Windows registry, App Paths, uninstall entries and the usual install folders, with no dependence on Steam or GOG.
  • Checks the official base packs at startup.
  • One game_<arch> module, built from the Prey SDK, runs single-player and multiplayer.

Modern Presentation

  • OpenGL by default, matching Prey's original interaction stages; an optional Vulkan renderer.
  • Baked light grids add indirect light to portal areas.
  • Shadow maps, cel shading and DDS texture replacements, inherited from openQ4 and still being checked against Prey.

Built for Current Systems

  • SDL3 window handling: windowed, borderless, desktop and exclusive fullscreen, and monitor selection.
  • Native Wayland or X11 on Linux, and a Steam Deck launcher.
  • Experimental multiplayer bots on Prey's own artificial player.

Getting Started

  1. Install Prey (2006). Leave it where it is; openPREY keeps to its own folder.
  2. Get openPREY. Build and stage it with the build guide, or unpack a package from the releases page once one is published.
  3. Keep folders distinct. Prefer separate Prey and openPREY folders. Never copy retail .pk4 files into basepr/.
  4. Launch the client. Run openPREY-client_x64 (.exe on Windows). openPREY finds your Prey install on its own.

Platform Notes

  • Windows x64 gets most of the runtime testing; Linux x64 is built in CI.
  • Set OPENPREY_FORCE_X11=1 on Linux to force the XWayland fallback.
  • On a Steam Deck, run openPREY-steamdeck.

If Auto-Detection Fails

Launch with +set fs_basepath "C:\path\to\Prey", pointing at the Prey root that contains base/, not at base/ itself. The getting-started guide lists every location openPREY checks.

Compatibility and Scope

In Place

  • Runs the official retail Prey (2006) assets with its own engine and game module.
  • Unified basepr/ runtime layout with openPREY's own pak0.pk4 and pak1.pk4.
  • Doom 3-lineage behaviour restored where Prey depends on it.

Boundaries

  • Mods built for the original proprietary Prey game DLLs won't load.
  • Every client and server in a multiplayer game needs a matching openPREY build.
  • Engine code stays GPL; SDK-derived game code stays under the Prey SDK EULA.

Compatibility work is ongoing. The rebase status ledger records what has been ported and how each piece was tested, and the development roadmap lists what comes next.

Building from Source

Meson is the canonical build entry point. Builds go to builddir/ and the runtime package is staged into .install/.

What Matters

  • The game library is built in place from src/game/, src/Prey/ and src/preyengine/.
  • One game_<arch> module for every mode.
  • Automated runs always stay windowed: +set r_fullscreen 0.

Windows Example

tools/build/meson_setup.ps1 setup builddir . --backend ninja --buildtype=release --wrap-mode=forcefallback
tools/build/meson_setup.ps1 compile -C builddir
tools/build/meson_setup.ps1 install -C builddir --no-rebuild --skip-subprojects

See the build guide for Linux and packaging.
