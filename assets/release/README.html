Release Package

The open-source engine and game-code replacement for Prey (2006). This package holds the openPREY binaries and the staged basepr/ runtime payload with its unified game module. Prey's own game data is not included.

Requirements

Game DataA legitimate Prey (2006) installation from the original discs or another legitimate source, with its retail base/ packs left unmodified so startup validation can recognise them.
SystemWindows 10 or 11 (x64), or a 64-bit Linux desktop comparable to Ubuntu 24.04 or newer running Wayland or X11. The package architecture must match your CPU.
GraphicsAn OpenGL driver with the ARB2-era vertex and fragment program support Prey's renderer path relies on. The optional Vulkan renderer needs a working Vulkan driver.
Input and AudioKeyboard and mouse and a working audio device. Controllers are optional.

If the game runs slowly, the console command autoDetectPerformancePreset picks a performance preset for your hardware. The presets are inherited from openQ4 and have not yet been tuned for Prey.

Getting Started

  1. Install Prey (2006) and leave its retail base/ folder where it is. openPREY ships none of Prey's game data.
  2. Extract openPREY into its own folder. On Windows, run the installer executable instead when the release provides one. On Linux, a release may also provide an AppImage: mark it executable with chmod +x openprey-*.AppImage and run it. The AppImage bundles openPREY's runtime libraries but still finds your separately installed Prey (2006) assets; it never contains them.
  3. Keep a clean layout. Preferably leave Prey in its own install folder and let openPREY find it. For a portable setup, copy Prey's base/ beside openPREY's basepr/. Never copy retail .pk4 files into basepr/; that folder holds only openPREY's own files.
  4. Run openPREY-client_x64.exe on Windows or openPREY-client_x64 on Linux. On a Steam Deck, use openPREY-steamdeck.
  5. Open docs/index.html for the full offline documentation, starting with the getting-started guide.
  6. If openPREY cannot find Prey, launch it with +set fs_basepath "C:\path\to\Prey", pointing at the Prey root folder that contains base/, not at base/ itself.

How openPREY Finds Prey

openPREY uses the first of these locations that contains Prey's base/ folder: an fs_basepath you set on the command line; the folder openPREY was started from; on Windows, the Human Head Studios, 2K Games and 3D Realms registry keys, the prey.exe App Paths entry and uninstall entries; then the usual CD-era install folders such as Program Files\Human Head Studios\Prey, or ~/Games/Prey on Linux.

Configs, saves and logs go to a per-user folder: %LOCALAPPDATA%\openPREY on Windows, ~/.local/share/openprey (or $XDG_DATA_HOME/openprey) on Linux.

Platforms

Windows x64The primary target, with the deepest runtime testing. The package carries its own static runtime and OpenAL32.dll, so no redistributable is needed.
Linux x64Built in CI on every push. Retail gameplay sign-off is still in progress.
Steam DeckUse the openPREY-steamdeck launcher included in Linux packages.
Other TargetsWindows ARM64, Linux ARM64 and macOS are not released for openPREY yet. Their inherited build support has no Prey runtime evidence behind it.

Linux Notes

  • SDL3 picks native Wayland or X11 automatically. Set OPENPREY_FORCE_X11=1 to force the XWayland fallback.
  • If a Wayland compositor has trouble with window decorations at startup, set OPENPREY_WAYLAND_DISABLE_LIBDECOR=1 for that launch.

Steam Deck Notes

  • The launcher exports OPENPREY_STEAMDECK=1 and starts the client with the steamdeck platform profile in windowed mode.
  • The profile turns on the gamepad, gyro aiming, trackpad menu control, touchscreen routing and a low-battery rumble cap. Prey's own default.cfg predates controller support, so bind the Deck's buttons in Options → Controls or from the console.
  • Run listControllers from the console when reporting Deck input, battery, gyro, touchpad or touchscreen issues, and see the Steam Deck guide.

Package Contents

ExecutablesopenPREY-client_<arch> and openPREY-ded_<arch>, the client and dedicated server, plus the renderer-gl and renderer-vk renderer modules.
Game Modulebasepr/game_<arch>: one unified module for single-player and multiplayer.
Runtime Databasepr/pak0.pk4, basepr/pak1.pk4 and basepr/mod.json: openPREY's own content and overrides.
Symbols*.pdb files on Windows, which make crash dumps actionable.
LaunchersopenPREY-steamdeck and desktop entries on Linux.
Documentationdocs/index.html, the offline portal, with the user guides under docs/docs/user/ and developer notes under docs/docs/dev/.
LicencesLICENSING.md explains the component terms. LICENSE and its Additional Terms cover the engine; licenses/PREY-SDK-EULA.rtf covers the SDK-derived game code. CONTRIBUTORS.md credits the people behind it.

Crash Reports

On Windows, an unhandled openPREY crash writes a crash log and a memory dump to crashes/ beside the executable. Attach both files when you report it.

For other problems, launch with +set logFile 2, reproduce the problem, and attach the qconsole.log it writes to basepr/ in your save folder. Include your platform, package name and how you installed Prey.
