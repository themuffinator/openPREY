# Unreleased openPREY changes

openPREY has no published release yet. [v0.0.1.md](v0.0.1.md) is the draft for the first release and describes the rebase onto the openQ4 engine as of August 2026. This file collects what changed after that draft, for curation when the first release is cut. It promises no version or date. The nightly builds on the Releases page date from April 2026, before the rebase, and contain none of this.

Engine changes merged from openQ4 are listed in openQ4's own release notes. They are inherited, not yet checked against PREY, until the [rebase status ledger](../prey-rebase/status-ledger.md) records evidence for them.

## Highlights

- **The game library is in this repository.** The PREY SDK-derived trees, `src/game/`, `src/Prey/` and `src/preyengine/`, were imported with their history from the former `OpenPrey-game` companion repository. Meson builds the unified `game_<arch>` module in place, so no companion checkout, configure-time staging or `OPENPREY_GAMELIBS_REPO` is needed. This supersedes the developer upgrade note in the 0.0.1 draft. The game trees stay under the PREY SDK EULA and the engine stays GPLv3; see [LICENSING.md](../../../LICENSING.md) and the [game source provenance record](../game-source-provenance.md).
- **Multiplayer bot characters (experimental).** Nineteen named bots built on PREY's own artificial player (`hhArtificialPlayer`), each with one of six fighting styles, a retail player model and its own chat lines, added with `addbot [character] [skill]`. Retail maps ship no bot navigation, so bots fight what they can see rather than planning routes. See the [bot guide](../mp-bots.md).
- **Damaged retail Ogg Vorbis files play through.** Sounds that stop early under stb_vorbis are decoded again with libvorbisfile (libogg 1.3.6 and libvorbis 1.3.7 Meson wraps), which resumes after a bad page instead of truncating the sound.

## Engine

- Merged openQ4 engine work through upstream `c47707b96` (20 November 2026), adapted to PREY's v7 game API. Earlier syncs brought the extended graphics presets with Auto-Detect, the classic menus laid out like the new interface, cached shadow casters and projected shadow maps on Vulkan, and display settings that apply without a device restart.
- The November 17 sync adds, from openQ4's engine: PNG textures and PNG screenshots (`r_screenshotFormat 1`); texture packs that replace `downsize()` inputs, decode BC7, and rebuild bump maps from replaced inputs, compressed; Vulkan textures reduced to fit video memory, and loading that stops on a lost device; OpenGL MSAA changes without a new window, OpenGL's post-processing chain cut to Vulkan's (half-resolution SSAO, no scene copies) and its scene target cleared each frame; optional character self-shadows under shadow maps (`r_shadowMapCharacterSelfShadow 1`, off by default), softer modern-OpenGL shadows (PCSS-lite), steadier still-light shadow caches and light-interaction cull bits computed in one pass; render demos recorded in checked blocks with keyframes (about 40% of the size, one-second seeks); network protocol 2.42 (keyed channel packets, server info and connect replies that fit one 1280-byte packet, snapshots replayed between tics, commands kept on time through long client frames, bounded client floods); a log file that stops logging instead of crashing when it cannot be written; and a mod's string tables read on top of openPREY's own.
- The November 20 sync adds: BC4, BC5 and BC6H (HDR) DDS textures, BC6H decoded to 16-bit floating point where the renderer lacks BPTC, and big texture packs that stay compressed; cascaded sunlight on the Quality and Ultra presets as well as Maximum, with the light's whole map kept past the cascades' reach and the normal offset of distant lights sized at each receiver's depth; OpenGL point-light shadow cubes drawn into one layered target; cheaper faded decals, particle expiry and idle reverb slots; a pack found under two search roots mounted only once; and the name of the loose file that makes a pack's DDS look stale.
- The menu's Updates check now asks openPREY's GitHub releases (openQ4's in-game updater) instead of the retail master server, which never knew openPREY builds. openPREY publishes no update manifest or signing key yet, so the check reports that it could not reach an update and offers the releases page; it never installs anything. `openPREY-updater_<arch>` is staged beside the client for when releases carry signed manifests.
- Not taken from that sync: its Quake 4 game code (Instagib, the Classic ruleset and grappling hook, buying, the map database and multiplayer modifiers, enhanced physics, weapon-fire shadows, the camera-kick option, the marines' flashlights) and its Quake 4 and Awakening content. The retained interface's new menu sound cue stream stays silent in openPREY: PREY declares neither of openQ4's stock cue sounds, and openPREY's retained documents name their own PREY sounds.
- Rebase hardening: guards for the render-demo header, the network rate defaults (32000), the GUI stream marker and window-flag layout, and the loading-music declaration scope; the missing autosave string `#str_107240`; lazy loading of dormant ARB programs; the particle deform implementation; and image alias handling.
- Shadow maps are the default shadow technique (`r_useShadowMap 1`) on every preset that draws shadows, Low, Performance and Balanced included; stencil volumes remain the per-light fallback. TrueType text is the default (`r_useTrueTypeFonts 1`). Configurations saved with the old values are moved to the new defaults once (`r_preyDefaultsMigrated`).
- Shadow maps of parallel lights, distant point lights and projectors store the triangles a stencil shadow is built from. They stored the opposite side, so in the Land of the Ancients maps the sun shone through canyon walls that stencil shadows: 5.7% of lotaa's start view and 12.4% of lotab's differed from the stencil picture, now 1.5% and 1.6% (shadow edges), on OpenGL and Vulkan. See the [shadow-mapping audit](../shadowmapping-audit-2026-11-09.md#correction-14-november-the-handedness-was-the-wrong-way-round-openprey).
- Levels load over their own loading art again, as in retail PREY: single-player levels showed the generic painting and multiplayer levels their 512 menu thumbnail. A new client-only content pack, `pak2.pk4` (269 MB), replaces 32 of the 33 in-game loading screens with recaptures taken at the retail cameras, recovered from the retail art, rendered with shadow maps for every light and extended with the tiles that fill wide and tall windows. `feedingtowera`, whose camera could not be recovered, keeps the retail art ([levelshot capture notes](../levelshot-capture.md)). `levelshot` writes PREY's `guis/assets/loading/<map>` by default.
- Surfaces drawn by PREY's own per-light shader programs (skin, cloth, hair, parallax, masked and the organic walls) take their shadows from a shadow-mapped light's map on OpenGL, with the same soft edges as everything else; they used the light's stencil volumes (`r_shadowMapProgramReceivers`, default 1).
- Beam effects are visible again: forcefield, laser and energy beams whose material turns them to the viewer (`deform beam`) were drawn edge-on and vanished. The beam model now builds retail PREY's ribbon, with the texture running once along the whole beam rather than once per segment.
- PREY's heat-haze, refraction and membrane programs keep their distortion under an off-axis projection (a levelshot's side tiles, a VR eye); it swelled into a smear there.
- A `levelshot` source larger than the window, rendered in regions, now matches a one-pass render, so supersampling is no longer capped at the window size. Each region fitted cascaded shadow maps to its own narrow frustum, and a shadowed surface could come out lit (in `keeperfortress`, a wall panel behind the glass and a wedge of the window frame); regions now use their whole tile's cascades, and the distortion programs' deform keeps the whole view's clamp and per-axis scale.
- Vulkan draws PREY's glow overlay: every `glowStage` material stage is redrawn into a black copy of the view, blurred per axis with `r_glowSteps`, `r_glowAlpha` and `r_glowAlphaChange`, and added over the scene at `r_glowStrength`, as the OpenGL renderer does.
- OpenGL's glow overlay follows retail PREY: the glow stages are reduced to a 256x256 image, blurred there with taps weighted by the square of the blur alpha, and stretched over the view. It was blurred at full size with taps weighted by the alpha itself, which drew glow about four times too strong and a seventh as wide, so the multiplayer maps' hexagonal wall-walk panels turned into thick white outlines and energy effects into opaque bursts. The glow also includes the stages of a view's portal sky, as retail's re-rendered glow view did; the overlay is skipped in views with no glow stage. Vulkan's overlay is unchanged.
- Fog and blend lights affect only surfaces with lighting stages, as in retail PREY (Doom 3's rule); they took ambient-only surfaces too (Quake 4's `noFog` rule), so a black fog in `dmshuttle1` painted the sky portal over its Earth window black.
- Classic GUI tabs now send the commands their `onTabActivate` scripts raise when the tab is switched to. Prey's menus get back the tab-flip sound and the scans each tab starts: player models on Player Settings, maps on Create Server, servers on Find Servers and control profiles on Profiles.
- A classic GUI script's `namedEvent` now sends the commands that the windows answering it raise, while the GUI is active. Opening MultiPrey refreshes the server list and checks for updates, and Options' Apply Changes (or leaving Options with a pending change) restarts the video mode.
- World GUIs now send the commands they raise when the game gives them a named event, as retail PREY did. A console that an AI uses triggers its targets and plays its sound, scripted consoles play their sounds, the roadhouse games reset, and the jukebox turns on and off.
- The server browser's status line and scan progress have openPREY strings in English, French, Italian and Spanish. Retail Prey's language files have none, so a scan logged an "Unknown string id" warning every frame, and the server count and mod filter showed bare string IDs.
- A server's details in the browser are labelled in English, French, Italian and Spanish: map, time and frag limits, team damage, team balance, pure and spectators. A passworded server reads "PASSWORD REQUIRED", as in retail PREY. The Quake 4 game types' labels no longer show lines of Tommy's dialogue.
- The classic GUI pointer is retail PREY's size: 16 canvas units on the menus (it was 15) and 32 on world GUIs (it was Doom 3's 64, twice retail's). `openq4_guiCursor <x> <y>` places a classic GUI's pointer for scripted captures.
- The in-game and system consoles use the PREY palette instead of Quake 4 amber and olive: the in-game console keeps a black field with portal-cyan text and edge, and the system console is dark Sphere-shell slate.
- Windows builds show the startup splash, as openQ4 does: a 512x384 borderless window, centred while the engine loads and closed when the game window opens. The Windows resource script never embedded `assets/splash/prey_rt_bitmap_4001.bmp`, so the splash had nothing to show.
- A first retained (vector) replacement of the main menu's navigation, off by default: `ui_retained 1` draws the home screen's arc of hooks, bottom bar and the New Game, Exit and Quit Game frames as resolution-independent vectors over the stock portal backdrop, out of game and in a single-player game. Load Game and Save Game are rebuilt the same way at the stock layout, with the saves table, the save's picture, the name field and the stock confirmations before deleting, overwriting or, in a game, loading. They add what the stock menu lacks: keyboard and controller navigation with a visible focus, and the whole row as the pointer's target. The death screen's frame and its Load, Restart and Main Menu buttons are rebuilt too, over the stock backdrop and fade. Mods is a frame of the title with the installed mods and Load MOD, and Credits is the stock roll, line for line, in a retained page. Options has its page, tabs and the Game Options, Video and Audio tabs rebuilt, with choice lists and sliders that change settings at once, a sound-device list that shows long names in full, and an Apply Changes button that is lit only while a setting that needs a video restart differs from what is in effect; its Controls tab, and MultiPrey, still open the stock pages. The documents (`guis/menu/title.rui`, `pause.rui`, `loadgame.rui`, `savegame.rui`, `restartmenu.rui`, `credits.rui`, `settings.rui`) are generated by `tools/ui/build_retained_screens.py` from the UI visual design specification, section 12.5.
- With `ui_retained 1` the engine starts on a retained initializing screen instead of the stock loading painting: a ball of portal energy sends a beam up into a lens flare that carries the PREY wordmark, over a slowly drifting nebula and star field, with the startup step and a progress rule beneath. It opens with a short entrance and keeps a still pose under reduced motion. Its document and textures are generated (`tools/ui/build_retained_initialization.py`), contain no retail art, and are described in section 12.6 of the UI visual design specification. The screen also follows Prey's startup steps now; it read Quake 4's string numbers before, so its progress never advanced.
- With `ui_retained 1` levels load under a retained loading screen (`guis/loading/loading.rui`), rebuilt from Prey's one loading screen at its measurements: the level's art across the screen, the name band with the level's name and author line, the objectives panel, and the progress bar in its claw-ended outline traced as vectors, with the loader's phase and count beside it. The session did not offer Prey's loading screen to the retained interface before, and no document existed.
- Loading pictures are found as retail Prey finds them: loading a save shows that save's screenshot, a level its own loading art, an addon map's art copied out of its pak, and otherwise the generic picture; the menus' thumbnails are no longer used for loading. The stock loading screen always showed the generic picture, because its default compared image names as numbers. A picture without the edge tiles a wide or tall window needs is drawn at 4:3 instead of with its edges stretched, and each composed picture has its own name.
- Retained menu refinements: Save Game and Credits are prepared while the pause rests, and Credits while the title does, so their first open no longer compiles their artwork in the frame that shows them. On Options, Up from a page's first control reaches that page's own tab (from Audio's first row it reached Video) and the bottom bar's ends stop the focus. The pause names Prey's difficulties, Normal and Cherokee, where it looked up Quake 4's ranks and logged an unknown string id each time it opened, and a level's load time has its openPREY string (`#str_231534`), whose absence logged another.

## Build and CI

- `openprey-validation.yml` builds the engine, dedicated server, OpenGL and Vulkan renderers and the unified game module as debug builds on Windows x64 and Linux x64, then checks the staged payload. The Linux lane installs its native development packages and the Windows lane prepares an OpenAL Soft runtime before staging.
- Fixed debug-only build failures in the game library on MSVC x64 and GCC, and header spellings that resolved only on case-insensitive filesystems.
- VS Code launch configurations come in OpenGL and Vulkan variants and cover the deathwalk maps.

## Documentation

- The player guides now describe openPREY only. Guides for Quake 4-only features carried in by engine merges were removed: The Awakening, campaigns, the Arena Campaign, competitive matches, liquids, classic dynamic lights, Android, the level editor and languages. The remaining inherited guides say where PREY testing is still pending.
- Getting Started, BUILDING.md, TECHNICAL.md and the contributing guide describe building from source, the Windows OpenAL runtime, the supported platforms (Windows x64 and Linux x64) and where configs, saves and logs go.

## Known Limitations

- Full campaign completion and multiplayer parity aren't claimed yet.
- Multi-view demos and the demo repeater are compiled out (`OPENPREY_ENABLE_MVD=0`, `OPENPREY_ENABLE_REPEATER=0`), along with openQ4's engine-side bot integration.
- ModernGL and Vulkan feature parity with PREY's original interaction stages is deferred; OpenGL stays the default.
- Checksums for the CD-era numbered `pak000.pk4`–`pak004.pk4` layout aren't recorded yet; those packs are checked for presence only.
- macOS, ARM64 and the inherited release, signing and publishing workflows stay switched off until they're rebuilt for openPREY.
